The 30-second mental model

Three facade objects cover almost everything you'll do:

ScallopQuery

Read protocol state — markets, your obligations, prices, portfolio. Returns plain typed objects.

ScallopClient

Do things in one call — supply, borrow, repay, stake. Builds, signs and sends a transaction.

ScallopBuilder

Compose custom transactions — chain multiple Move calls into one transaction block, then sign.

When you call a read like getMarketPools(), the SDK fetches from the Scallop indexer first (fast) and silently falls back to Sui RPC (authoritative) on failure, normalises the shape, and hands you a typed result. The How data is served view shows that pipeline end to end.

Use the SDK

Initialize

One Scallop instance is the entry point. Its factory methods build and auto-initialize the model you ask for.

Constructor parameters you'll actually use

paramtypepurpose
addressIdstringScallop's published address bundle id (mainnet).
networkType'mainnet'Network. Mainnet only today.
secretKeystringSigner key — only needed for write paths that sign.
walletAddressstringDefault sender/owner for reads & tx building when not signing.
loggerLoggerOpt into diagnostics — defaults to silent noopLogger.
queryClientConfigobjectTune the TanStack cache (staleTime, gcTime).
force*InterfaceobjectOverride addresses / pool addresses / whitelist (tests, custom deployments).
Read vs write: reads need no key. To sign & send you need secretKey; to merely build a transaction for an external wallet to sign, you don't — pass sign: false and you get back a transaction block.

Coin names & amounts — read this once

Two conventions trip up newcomers. Learn them now and every method makes sense.

Coin naming

kindexamplewhat it is
underlying coin'sui'the asset itself
wrapped variant'wusdc'e.g. Wormhole USDC vs native 'usdc'
market / sCoin'ssui'interest-bearing receipt for supplied 'sui'

Supply/borrow/collateral methods take the coin name ('sui'). Spool stake/unstake and sCoin methods take the sCoin name ('ssui').

Amounts are raw base units

Every amount is an integer in the coin's smallest unit — no decimals. Multiply by 10 ** decimals yourself.

Read data with ScallopQuery

All reads are async and return plain typed objects. Pick a domain.

getUserPortfolio is the heavy composite read — it fetches several domains in parallel, then assembles them with pure functions. See How data is served.

Do actions with ScallopClient

High-level one-call actions. They build the transaction, then — by default — sign and send it.

The sign flag. Most write methods take sign as the 3rd argument, defaulting to true. true → signs & sends, returns the transaction response. false → returns an unsigned transaction block for you to sign with your own wallet.

Borrow & withdraw-collateral need fresh oracle prices. The client/quick methods update them for you automatically.

Compose transactions with ScallopBuilder

When one action isn't enough, build a transaction block and chain calls. Two flavours per operation:

…Quick methods

Normal methods

Thin, synchronous Move-call wrappers returning a TransactionResult you wire by hand. Use for full control.

How data is served

What happens when you call a read

A read travels through a fixed pipeline. Press Play to trace query.getMarketPools(), or switch the data source to see how the same call resolves.

source:
Press Play. With api-first the indexer branch runs first; on any error it transparently retries on-chain.

Where each read comes from

Every domain declares a default source. Reads are indexer-first where an indexer endpoint exists, and on-chain where the data is too live or too specific to aggregate.

dual-source (indexer + RPC fallback) on-chain only api (Pyth/indexer)
sourcedomainswhy
dual market · spoolHeavily-read, aggregatable — indexer is fast; RPC is the safety net.
api priceLive oracle prices come straight from Pyth.
onchain obligation · coinBalance · borrowIncentive · veSca · isolatedAssets · xOracle · loyaltyProgram · referral · poolAddresses · flashloan User-specific or low-latency-sensitive — read directly from the chain.
You can override per call. Methods accept legacy flags (source, indexer, useOnChainQuery) which normalise to one QuerySource: 'onchain' | 'api' | 'api-first'. Force on-chain when you need the absolute latest value, e.g. query.isIsolatedAsset('deep', true).

Indexer-first, with graceful fallback

The choice of source is a Strategy. On api-first it tries the indexer, logs a warn through your logger if it fails, and falls back to RPC — your code sees the same shape either way.

Indexer — fast & aggregated

Pre-computed, batched, cheap. Slightly behind head. Best default for dashboards and lists.

On-chain — authoritative & live

Read straight from Sui, exact to the latest checkpoint, but heavier. Force it when correctness beats speed.

How a raw payload becomes a typed object

On-chain reads pass through a funnel: raw wire fields → normalised → parsed numbers → derived metrics → the public shape you receive. Each stage is a pure function.

Move event JSON
raw wire — gRPC/JSON-RPC, stringy, nested { value }
↓ mapper
Origin*Data
normalised — one stable shape; gRPC vs JSON-RPC differences gone
↓ parseOrigin*
Parsed*Data
typed — strings → numbers, scaled by decimals
↓ calculate*
Calculated*Data
derived — APR/APY, utilization, conversion rate
↓ assemble
MarketPool
public — the typed object you receive
Gotcha: parseObjectAs<T>. When the on-chain JSON has a value field it returns fields.value directly — not { value }. Zod schemas must match the unwrapped type. #1 source of empty-parse bugs.

Caching & request dedup

Every network read flows through fetchWithCache, backed by a shared TanStack QueryClient. Identical reads dedupe and serve from cache within staleTime.

Keys are centralised

All cache keys come from constants/queryKeys.ts, namespaced by source (queryKeys.api.*, queryKeys.rpc.*) and including the node URL so different fullnodes don't collide.

Tune it at construction

Composite reads: fetch in parallel, build pure

Reads that span domains (lending, obligation accounts, portfolio) follow one shape: the facade fetches everything in parallel, then a pure builder assembles the result — no I/O in the math.

The build* functions and all financial math live in services/query/portfolioCalculations.ts and are unit-tested with plain objects — no network. That's why they're pure.

The golden rule: a repository never imports a model. The single seam where models meet repositories is wiring/metadata.ts, which projects the model surface into plain data. That inversion is what makes the read layer testable without a network.

Model dependency chain

The facade classes compose in a chain; each exposes the next via a getter, and .init() cascades down.

Scallop
 └─ ScallopClient            // write · sign · send
     └─ ScallopBuilder       // tx blocks

             └─ ScallopUtils  // the deps hub

                 ├─ ScallopSuiKit     (wraps @scallop-io/sui-kit)
                 └─ ScallopIndexer    (REST indexer via axios)

The BaseRepository contract

All fourteen repos extend one generic base — Template Method: the base owns cache/logger/onchain/metadata, each domain fills the abstract context.

Wiring & the composition root

Repos are pure and model-agnostic, so wiring/ assembles them. It's the only place that knows both worlds.

registry.ts

Lazy, memoised registry of all 14 repos.

datasources.ts

Model → datasource adapters.

metadata.ts

The seam: project models → plain data.

source.ts

Normalise legacy flags → QuerySource.

The facade owns it lazily: get repos() { return (this._repos ??= createRepositories({ utils: this.utils })); }

Design pattern catalog

01 Repository ›

Per-domain class abstracting "how do I read this." Lives in: every repositories/<domain>/index.ts.

02 Composition Root + lazy Registry ›

createRepositories builds the graph; getters memoise. Lives in: wiring/registry.ts.

03 Strategy + graceful fallback ›

runWithDataSourceFallback picks api/api-first/onchain with a degrade path. Lives in: repositories/utils.ts.

04 Anti-corruption layer ›

mappers/ normalise gRPC vs JSON-RPC; wiring/metadata.ts keeps model types out of repos.

05 Functional core, imperative shell ›

Pure helpers + pure build*; thin async methods do the I/O. Lives in: helpers.ts, portfolioCalculations.ts.

06 Structural dependency injection ›

ClientServiceContext, BaseContext, *RepoContext are interfaces — real object in prod, literal in tests.

07 Template Method ›

BaseRepository implements caching + baseContext; abstract context is the hook.

08 Adapter ›

OnChainDataSource narrows the Sui client; datasources.ts adapts ScallopSuiKit.

09 Proxy composition ›

createTxBlock() layers 7 builders behind one Proxy. Lives in: builders/index.ts.

10 Facade ›

The models present a stable API; the whole refactor shipped with zero public signature changes.
